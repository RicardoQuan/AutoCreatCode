# 方法输出状态码编辑设计

状态：用户已于 2026-10-26 确认从节点面板修改时同步更新共享方法定义。

## 目标

让 `int` 返回值方法的返回状态码可以在方法库和流程节点面板中编辑、增加和删除。状态码属于方法的输出契约，两处编辑都修改同一份方法定义。

## 用户可见行为

- 方法库的函数编辑窗口和绑定该方法的节点面板都显示可编辑的状态码列表，提供添加、修改、删除操作。
- 节点面板编辑状态码后，方法库中的方法定义及所有绑定同一方法的节点同步更新。
- `int` 方法的 `0` 状态始终存在，不能删除。`bool` 方法仍使用固定的 `true` 和 `false` 分支；其他返回类型没有整数状态码编辑器。
- 添加状态只修改方法输出契约，并让该状态出现在节点的输出端口。用户可以在节点的“添加输出分支”中为未连接状态选择目标；既有逻辑会自动生成连线。
- 删除状态时，如果任一绑定节点仍有该状态的显式连线，拒绝删除并指出需要先处理相关分支，避免留下失效连线。
- 方法级等待/报警分类和节点配置的等待码引用到的状态，不能从结果列表中直接删除，避免留下无效分类或等待配置。
- 方法卡片继续显示当前输出状态码。状态列表改变后重新渲染，使方法卡片、节点端口、校验和方法库导出使用同一组值。
- 将方法状态列表的变更同步写回方法源代码中的 `FlowStatusCodes` 或 `FlowMethod` 状态参数，同时保留函数体和其他元数据，确保导出、重载 `.cs` 后状态不会回退。

## 数据与边界

- `ResultStatusCodes` 是 `int` 方法的唯一状态码来源；节点不保存独立覆盖值。
- 状态码按唯一整数规范化。改变顺序只影响列表展示顺序，不改变现有连线的状态值、目标或优先级。
- 每条显式状态连线仍由节点的 Transition 表示。添加状态后若尚未建立 Transition，现有流程校验提示该状态缺少分支。
- 编辑方法库与节点使用同一个方法对象和状态码校验规则；更新后的方法源码应由 C# 解析器重新读取并得到相同的状态集合。

## 验收

1. 在方法库中编辑 `0, 1, 9`，保存后方法卡片、画布出口和绑定节点都显示新状态集合。
2. 在一个绑定节点中增加状态码，其他绑定节点和方法库同时更新；该节点可以用“添加输出分支”为新状态建立并显示连线。
3. 删除仍被任一绑定节点连线使用的状态时，操作被拒绝，原有状态和连线保持不变。
4. `0` 不可删除；重复值去重；非法整数不保存；`bool` 分支继续为 `true / false`。
5. 更新后的 C# 源码重解析后仍包含相同 `ResultStatusCodes`，函数体及非状态属性保持不变。
